# 할 일 드래그 시 창 이동 수정

> 개발하면서 남긴 작업 기록이에요(공개 저장소에서는 날짜와 당시 스냅숏 이미지를 뺐어요). 지금의 설계와 과정은 [`docs/`](../../docs)에 정리돼 있어요.

## 문제와 수정

창 배경 이동 설정만 끄는 것으로는 직접 호출되는 창 이동과 목록 드래그를 충분히 분리하지 못했다. 상단 NSView 배경 드래그를 삭제하고 NoteWindow 한 곳에서 좌표를 확인한다. 기본 상태에서는 창 이동을 비활성화하고, 상단 132pt 중 창 제어 버튼을 제외한 영역에서만 명시적으로 창 이동을 허용한다.

목록 손잡이는 시스템 간 드래그/드롭 전달 대신 같은 창의 마우스 추적을 사용한다. 포인터 위치로 삽입선을 정하고 마우스를 놓을 때 한 번만 순서를 저장한다. 창 밖이나 목록 밖에 놓기/ESC는 취소한다. 기존 위/아래 이동 메뉴 및 접근성 동작도 유지한다.

## 변경 파일

- Sources/PaperTodo/NoteWindow.swift: 창 이동 영역과 입력 처리, 선택적 진단 로그.
- Sources/PaperTodo/PaperTaskDragHandle.swift: 손잡이 마우스 추적과 삽입 위치 계산.
- Sources/PaperTodo/PaperView.swift: 목록의 공유 이동 상태 및 삽입선, 기존 배경 드래그 뷰 제거.
- Sources/PaperTodo/PaperTodoApp.swift: 분리된 NoteWindow 사용, 앱 버전 표시 수정.
- Tests/PaperTodoTests/PresentationTests.swift: 창 영역과 삽입 경계 회귀 검사.
- Resources/Info.plist: 1.7.1 / build 9.

외부 의존성은 추가하지 않았다. 중복 창 이동 경로 및 문자열/비동기 아이템 제공자 기반 목록 드롭 경로를 제거했다.

## 실제 QA 증거

별도 저장 파일 .build/qa/window-drag-regression.json 사용. 실제 마우스 드래그로 책 읽기 항목을 세 번째에서 마지막으로, 다시 맨 위로 이동한 것을 UI와 저장 파일에서 확인했다. 두 이동 전후의 창 좌표는 (645,384)로 유지됐다. 이벤트 로그는 .build/qa/window-drag-events-fixed.jsonl에 기록했다.

진단 로그는 --interaction-log 경로를 명시한 QA 실행에서만 기록되며, 일반 실행에서는 기록하지 않는다.
