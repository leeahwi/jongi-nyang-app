# 할 일을 끌 때 창이 같이 움직이던 것 고치기 (1.7.1)

> 개발하면서 남긴 작업 기록이에요(공개 저장소에서는 날짜와 당시 스냅숏 이미지를 뺐어요). 지금의 설계와 과정은 [`docs/`](../../docs)에 정리돼 있어요.

## 문제와 고친 방법

이제 할 일 줄을 끌면 순서만 바뀌고 창은 그대로예요. 창은 위쪽 132pt 영역(창 버튼 제외)을 끌 때만 움직여요.

창 배경으로 창을 옮기는 설정만 끄는 것으로는, 직접 부르는 창 이동과 목록 끌기를 충분히 떼어 놓지 못했어요. 그래서 위쪽 NSView의 배경 끌기를 지우고, NoteWindow 한 곳에서 좌표를 확인해요. 기본 상태에서는 창 이동을 꺼 두고, 위쪽 132pt 가운데 창 버튼을 뺀 영역에서만 창 이동을 직접 허용해요.

목록 손잡이는 시스템의 끌어 놓기(drag and drop) 전달 대신 같은 창 안의 마우스 추적을 써요. 포인터 위치로 끼워 넣을 선을 정하고, 마우스를 놓을 때 한 번만 순서를 저장해요. 창 밖이나 목록 밖에 놓거나 ESC를 누르면 취소해요. 예전의 위 · 아래로 옮기기 메뉴와 손쉬운 사용 동작도 그대로예요.

## 바꾼 파일

- Sources/PaperTodo/NoteWindow.swift: 창 이동 영역과 입력 처리, 필요할 때만 켜는 진단 기록.
- Sources/PaperTodo/PaperTaskDragHandle.swift: 손잡이의 마우스 추적과 끼워 넣을 위치 계산.
- Sources/PaperTodo/PaperView.swift: 목록이 함께 쓰는 이동 상태와 끼워 넣을 선, 예전 배경 끌기 뷰 제거.
- Sources/PaperTodo/PaperTodoApp.swift: 떼어 낸 NoteWindow 사용, 앱 버전 표시 수정.
- Tests/PaperTodoTests/PresentationTests.swift: 창 영역과 끼워 넣기 경계 회귀 검사.
- Resources/Info.plist: 1.7.1 / build 9.

외부 의존성은 더하지 않았어요. 겹치던 창 이동 경로와, 문자열 · 비동기 아이템 제공자(item provider)로 목록에 놓던 경로를 지웠어요.

## 실제 QA에서 확인한 것

따로 만든 저장 파일 .build/qa/window-drag-regression.json을 썼어요. 실제 마우스로 ‘책 읽기’ 항목을 세 번째에서 마지막으로, 다시 맨 위로 옮긴 것을 화면과 저장 파일에서 확인했어요. 두 번 옮기는 동안 창 좌표는 (645,384) 그대로였어요. 이벤트 기록은 .build/qa/window-drag-events-fixed.jsonl에 남겼어요.

진단 기록은 --interaction-log 경로를 직접 준 QA 실행에서만 남고, 평소 실행에서는 남기지 않아요.
