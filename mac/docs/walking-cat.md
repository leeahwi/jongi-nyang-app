# 종이냥 걸어오기 (1.8.0)

> 개발하면서 남긴 작업 기록이에요(공개 저장소에서는 날짜와 당시 스냅숏 이미지를 뺐어요). 지금의 설계와 과정은 [`docs/`](../../docs)에 정리돼 있어요.

쪽지 · 친구 알림이 오면 고양이가 화면 오른쪽에서 1.8초쯤 걸어 들어온 뒤, 0.24초 동안 말풍선을 열고 손을 흔들어요. 원래 그림을 바탕으로 두 발이 번갈아 움직이고, 몸이 조금 흔들리고, 그림자가 따라오게 만들었어요. 미니 알림은 캐릭터 없이 바로 떠요.

알림을 보여 주는 시간은 말풍선이 다 열린 뒤부터 세요. 걷는 동안 투명한 창이 클릭을 가로채지 않아요. 마우스를 올리거나 메뉴를 여는 동안 자동으로 닫히지 않는 것, 새 알림이 오면 바꾸고 닫을 때 하던 일을 취소하는 것은 그대로예요. macOS의 동작 줄이기를 켜면 걸어오기와 손 인사를 건너뛰어요.

바꾼 파일:

- Sources/PaperTodo/ReminderController.swift / TaskReminderController.swift: 도착한 뒤 진단 캡처.
- Tests/PaperTodoTests/DesignSnapshots.swift: 걷는 중 · 도착하는 중 · 알림을 보여 주는 프레임과 실제 창 좌표.
- Tests/PaperTodoTests/PresentationTests.swift: 새 알림으로 바꾸기 · 닫기와 읽는 시간 지키기 회귀 검사.
- Resources/Info.plist, README.md: 버전과 쓰는 법.

확인한 것:
- 경고를 오류로 보는(warnings-as-errors) 디버그 · 릴리스 빌드가 통과했어요.
- 관련 화면 검사 10개가 통과했어요.
- 네이티브 렌더 타임라인에서 창 X가 1637 → 1406 → 1248로 움직이고, 진행도가 1에 닿은 뒤에만 말풍선과 읽기 타이머가 켜지는 것을 확인했어요.
- 실제 QA 앱에서 설정 → 알림 → 미리보기를 실행했어요.
- 새 비트맵 그림이나 외부 의존성은 더하지 않았어요.

## 1.9.0 걸음 다듬기

**어색했던 이유**
- 앉아 있는 정면 그림의 아래 14%를 잘라내고, 그림체와 다른 타원 몸통 · 발 두 개를 붙였어요. 목도리 아래가 끊겨 인형극처럼 보였어요.
- 같은 속도로 미끄러지다 갑자기 멈췄어요. 발 움직임이 이동 거리와 상관없어서 발이 헛도는 느낌이었어요.
- 창 전체를 16ms마다 옮겨서 SwiftUI 그리기와 박자가 어긋났고, 오른쪽에 모니터가 있으면 그 화면에서 출발했어요.
- 도착한 뒤, 앞발 두 개가 이미 그려진 그림 위에 세 번째 발을 덧그려 흔들었어요.

**바꾼 방식**
- 원본 그림은 그대로 두고, 한쪽 앞발(가로 39% / 56% 지점)을 축으로 ±7° 기울여 반대 발이 들리게 걸어요. 걸음 수가 이동 거리에 묶여 있어서, 느려지면 걸음도 느려져요.
- 거의 같은 속도로 걷다가 마지막 걸음에서 절반 속도로 줄고, 마지막으로 디딜 때의 눌림이 그대로 도착 스프링으로 이어져요.
- 창은 제자리에 두고 화면 가장자리까지 넓혀서, 고양이만 창 안에서 움직여요. 화면 끝이 자연스럽게 고양이를 가려요. 움직임은 `TimelineView`에서 시간에 대한 순수 함수(`MascotMotion.pose`)로 계산해요.
- 말풍선은 꼬리 위치를 기준으로 스프링처럼 열리고, 친구 모드는 꼬리를 입 높이로 올렸어요.
- 세 번째 발 대신 폴짝 인사 → 고개 갸웃 → 숨쉬기를 해요.
- 저절로 닫힐 때는 말풍선을 접고 걸어 나가요. 버튼으로 닫거나 완료 · 미루기를 누르면 바로 닫혀요. 동작 줄이기를 켜면 걷기 · 폴짝 · 기울이기를 모두 건너뛰어요.

**확인한 것:** warnings-as-errors 디버그 · 릴리스 빌드, 화면 검사 12개(걷기 시작 · 끝이 이어지는지, 뒤로 미끄러지지 않는지, 걸어 나간 뒤 닫히는지 포함)와 기존 회귀 검사 60개가 통과했어요. 실제 SwiftUI 렌더로 걷기 · 도착 · 인사 · 나가기 프레임을 확인했어요. 실제 화면에서 60fps로 움직이는 모습을 눈으로 보는 일은 렌더 검사로 대신할 수 없어서, 아직 사람 눈으로 봐야 해요.
