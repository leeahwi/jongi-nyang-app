# 하루 일정표 블록 끌기 — 떨림과 계단 움직임 (원인과 수정 기록)

- 영향: Mac 1.40.0–1.40.1, Windows 1.25.0–1.25.1 (하루 띠를 펼친 "하루 전체" 일정표)
- 수정: Mac 1.41.0, Windows 1.26.0
- 발견: 직접 쓰다가. "박스를 옮기면 매끄럽지 않고 떨린다."

## 증상

| | 보이던 것 |
| --- | --- |
| Mac | 블록을 아래로 계속 끌어도 블록이 원래 자리와 한 칸(15분, 12.5pt) 아래를 오가며 떨렸다. 끝을 놓기 전까지 포인터와 최대 51.5pt 어긋났다. |
| Windows | 떨지는 않았지만 계단처럼 움직였다. 가만히 있다가 12.5px씩 툭 뛰었고, 포인터와 최대 6px 어긋났다. 216프레임 중 포인터와 1px 안에 있던 건 38프레임. |

## 원인

### Mac — 움직이는 블록 기준으로 거리를 쟀다

1.40의 블록은 `DragGesture`를 블록 자신에 붙였고, 좌표 공간은 기본값인 `.local`이었다. 그리고 블록을 `.offset`으로 15분 단위(12.5pt)씩 옮겼다.

`.local`은 블록 기준이다. 블록이 한 칸 내려가면 기준도 한 칸 내려간다. 그래서 제스처가 다음에 알려 주는 이동량은 "포인터가 움직인 거리 − 블록이 이미 움직인 거리"가 된다. 이 값을 다시 15분 단위로 맞추면 방금 내려간 한 칸이 취소되고, 그다음 이벤트에서 다시 내려간다. 포인터가 꾸준히 내려가는 동안 블록은 0 / 12.5 / 0 / 12.5를 오갔다.

```
틱  포인터  제스처가 본 이동량(= 포인터 − 블록 위치)  블록 위치(= 12.5 단위로 맞춤)
 3    5.2     5.2                                    0.0
 4    6.5     6.5                                   12.5   ← 한 칸 내려감
 5    7.8    -4.7                                    0.0   ← 기준도 내려가서 다시 취소
 6    9.1     9.1                                   12.5
 7   10.4    -2.1                                    0.0
```

같은 포인터 경로(118틱)를 1.40의 계산에 넣으면 블록 위치가 114번 바뀌고, 그중 61번은 포인터와 반대 방향이었다. 이 표는 실제 측정이 아니라 옛 코드의 계산을 그대로 재현한 것이다(`scripts/drag-sim-1.40.py`).

덤으로, 끌고 있는 상태를 일정표의 `@State`에 두어서 한 칸 움직일 때마다 일정표 전체와 모든 블록을 다시 그렸다.

### Windows — 맞춰진 자리를 바로 그렸다

포인터는 화면 좌표로 제대로 쟀다. 그래서 Mac 같은 되먹임은 없었다. 대신 `pointermove`마다 15분 단위로 맞춘 자리(`draggedSpan`)를 블록의 `top`에 바로 써서, 블록이 포인터 대신 15분 칸을 따라 뛰었다.

같이 찾은 문제:
- 끄는 중에 스크롤하면 블록이 어긋났다(화면 좌표만 쓰고 스크롤 양을 더하지 않음). 자동 스크롤도 없었다.
- 놓은 지점이 아니라 마지막 `pointermove` 지점에 놓였다.
- 할 일을 끌어서 끝이 04:00이 되면 저장소가 조용히 거절했는데도 "옮겼어요"가 떴다.

## 고친 방법 (두 앱 같음)

1. **포인터는 일정표 기준으로 잰다.** 일정표 화면 좌표 + 스크롤 양. 움직이는 블록 기준으로 재지 않는다.
2. **끄는 동안 블록은 포인터를 그대로 따라간다.** 15분 단위로 맞추는 건 놓을 때만. 끄는 동안에는 맞춰질 자리를 점선 윤곽과 시간 표시로 따로 보여 준다.
3. **끄는 동안에는 데이터에 쓰지 않는다.** 놓을 때 한 번만 쓰고, 120ms 동안 맞춰진 자리로 들어간다(움직임 줄이기면 바로).
4. **다른 블록은 다시 그리지 않는다.** Mac은 끄는 상태를 끌리는 블록과 점선만 읽는 `@Observable` 객체로 옮겼다. Windows는 끌리는 블록의 스타일과 점선만 바꾼다. 블록의 열과 폭도 끄는 동안 고정한다.
5. 위아래 24pt 안에서 머무르면 자동 스크롤, Esc나 포인터를 놓치면 취소.
6. 같은 계산 위에 **위·아래 끝 늘리기**를 얹었다. 끝은 가장 가까운 15분에, 최소 15분, 할 일의 끝은 그날 03:45까지.

계산 규칙은 두 앱이 같은 사례 표로 확인한다. 옮기기·늘리기 R1–R8과 04:00 경계 W3이다. Mac은 `Tests/PaperCoreTests`, Windows는 `test/dayStrip.test.ts`에 있다.

### 어떻게 쟀나

- **Mac**: 테스트용 사본에 보낸 가짜 마우스 이벤트는 SwiftUI `DragGesture`까지 가지 않았다. 그래서 디버그 빌드에만 있는 재생 장치(`--timetable-replay`, `TimetableReplay.swift`, `#if DEBUG`)가 제스처와 같은 함수를 초당 60번 부르고, 매 틱 블록이 그려진 위치를 기록한다. `scripts/drag-check.sh`가 테스트용 사본을 만들어 재생하고 `drag-check.py`로 판정한다.
- **Windows**: CDP로 실제 마우스 이벤트를 1px씩 보내고, `requestAnimationFrame`마다 블록의 `top`을 기록했다(`tools/drag-probe.mjs`).

## 다시 생기지 않게

- 끌기 · 늘리기 같은 연속 입력은 **움직이는 대상이 아니라 고정된 컨테이너 기준으로 잰다.**
- 끄는 동안의 위치와 저장되는 값(15분 단위)을 **분리한다.** 화면은 포인터를, 데이터는 놓을 때만.
- 끄는 동안 **전체를 다시 그리지 않는다.** 바뀌는 건 끌리는 것과 미리보기뿐.
- 끌기를 고치면 `scripts/drag-check.sh`(Mac) / `tools/drag-probe.mjs`(Windows)로 틱마다 포인터와의 차이를 다시 잰다.

## 남은 것

- Mac에서는 실제 마우스·트랙패드 끌기와 커서 모양 바뀜을 자동으로 확인하지 못했다(재생 장치로 같은 경로만 확인).
- Windows는 실제 Windows PC, 고배율, 터치·펜 입력에서 확인하지 못했다.
- 03:30 이후에 시작하는 시작 시간만 있는 할 일의 위 끝을 늘리면 04:00 끝이 저장되지 않는다(할 일의 끝은 04:00을 저장하지 않음).
