# 할 일 스페이스 1단계: 구현 사양 (Mac 1.45.0 · Windows 1.30.0)

기획은 [spaces.md](spaces.md)이고, 시안은 [spaces-mock.png](spaces-mock.png)예요. 이 문서는 두 앱이 똑같이 만들 규칙과 공유 사례예요. 구현하면서 정한 것은 맨 아래 `## 정한 것 (구현 중)`에 적어요. 두 앱이 서로 읽고 맞춰요.

## 0. 범위

**1단계에 넣는 것**
- `todo-spaces.json`: 읽기, 쓰기, 합치기, 백업
- 오늘 한 장의 색 띠(①)
- 한 스페이스만 보기(②)
- 입력 줄과 빠른 입력의 `#스페이스`(③)
- 할 일 우클릭 → 스페이스로 옮기기, 할 일 고치기 쪽지의 스페이스 칸, 책상의 **스페이스** 칸(⑤)
- 도움말, ko · en · nl, 대비 · 스냅숏 · 성능 점검

**1단계에서 하지 않는 것 (2단계)**
- 스페이스별로 묶기(④)
- 앞으로 탭 · 하루 띠 · 하루 일정표 · 메뉴 막대 오늘 창 · 집중 카드의 색 띠와 거르기
- 반복 규칙(series)의 스페이스
- 검색 `#`
- 완료 · 집중 기록의 스페이스
- Claude 도구
- 1단계에서 거르기는 **오늘 탭의 할 일 목록에만** 적용돼요.

## 1. 데이터: `todo-spaces.json` (저장 폴더, `todos.json` 옆)

```json
{
  "version": 1,
  "spaces": [
    { "id": "s-7f3a9c", "name": "회사", "color": "pink", "order": 0, "updatedAt": "2026-10-28T09:00:00Z" },
    { "id": "s-02b1de", "name": "집", "color": "mint", "order": 1, "updatedAt": "…", "deleted": true }
  ],
  "items": {
    "<todo uuid>": { "space": "s-7f3a9c", "at": "2026-10-28T09:01:00Z" },
    "<todo uuid>": { "space": null, "at": "…" }
  }
}
```

**스페이스(`spaces`)**
- `id`: `s-` + 소문자 16진 6자리, 만들 때 무작위로 정해요.
- `color`: 메모 폴더와 같은 8색 키(`lavender pink mint yellow sky peach sand gray`)예요. 모르는 키는 그대로 두고 lavender로 그려요.
- `deleted: true`는 지운 표시예요. `updatedAt`부터 30일 지나면 파일에서 뺄 수 있어요.

**할 일의 자리(`items`)**
- `space: null`은 ‘스페이스 없음으로 옮김’이에요. 합치기에서 이 기록이 이겨야 하므로 지우지 않고 남겨요.
- 정리 규칙: 할 일이 `todos.json`에 없고 `at`이 30일보다 오래되면 저장할 때 빼요. 끝내서 archive로 간 할 일도 여기에 해당해요.

**모르는 키**
- 맨 위, 스페이스, 자리 모두 모르는 키를 읽은 그대로 남겨요(1.44 메모 서랍 규칙과 같아요). 2단계의 `series` 같은 키가 그렇게 살아남아요.

**합치기 (공유 폴더, 다른 기기의 저장)**
- 스페이스는 `id`로 합치고, `updatedAt`이 늦은 쪽이 이겨요(지운 표시 포함).
- 자리는 할 일 id별로 `at`이 늦은 쪽이 이겨요.
- 같은 시각이면 파일에 이미 있는 쪽을 둬요.

**읽기**
- 지운 스페이스나 없는 스페이스를 가리키는 자리는 ‘스페이스 없음’으로 읽어요. 파일은 고치지 않아요.
- 읽을 수 없는 파일은 `todo-spaces.json.unreadable-<시각>`으로 옆에 남기고 빈 상태로 시작해요.

**쓰기**
- 키를 정렬하고 들여쓰기 2칸, 끝에 줄바꿈을 넣어요(두 앱이 같은 바이트를 써요).
- 시각은 UTC ISO 8601, 초 단위예요.

**옛 버전과 함께 쓸 때**
- `todos.json`의 모양은 그대로예요.
- 옛 앱이 만든 할 일은 자리가 없으니 ‘스페이스 없음’이에요.

**백업(.jongi)**
- `todo-spaces.json`을 담아요.
- 가져오기의 ‘합치기’는 위 합치기 규칙을 따르고, ‘바꾸기’는 통째로 바꿔요.

**기기 설정(공유하지 않음)**
- 한 스페이스만 보기 상태: `{ spaceId, day }`예요. `day`는 4시 규칙의 논리 날짜 `yyyy-MM-dd`예요.

## 2. 입력 줄 `#스페이스`

**토큰**
- `#` 바로 앞이 줄의 시작이거나 공백이고, `#` 뒤에 공백이 아닌 글자가 1자 이상 이어지는 것이에요.
- 숫자로만 된 것(`#1`, `#2024`)과 `C#` · `a#b`처럼 앞에 글자가 붙은 것은 토큰이 아니에요.
- 한 줄에서 **첫 번째 토큰만** 써요. 나머지 토큰은 제목에 그대로 남아요.

**스페이스 찾기**
- 대소문자를 가리지 않고 이름의 공백을 무시해서, 아래 순서로 찾아요.
  1. 이름 전체가 같음
  2. 이름이 토큰으로 시작함(앞부분). 여럿이면 스페이스 순서상 첫 번째
  3. 토큰이 모두 한글 초성이고, 이름의 초성이 그것으로 시작함(`#ㅎㅅ` → 회사)
  4. 없음: `새 스페이스 ‘<토큰>’`. 넣을 때 다음 색(순서대로 8색 순환)으로 만들어요.
- 지운 스페이스는 찾지 않아요.

**넣을 때**
- 토큰과 그 앞의 공백 하나를 제목에서 빼요.
- 할 일이 아닌 것(일정 · 타이머 · 알람 · 메모)도 토큰은 빼지만, 스페이스는 붙이지 않아요.
- 제목이 토큰뿐이면(`#회사`만) 넣지 않아요. 입력 줄 안내는 ‘할 일 내용을 적어 주세요’예요.

**칩**
- 할 일 칩 옆에 `● 회사` 칩이 생겨요. 새 스페이스면 `+ 새 스페이스 ‘회사’`예요.
- `Tab`은 지금처럼 뜻(할 일/일정/…)을 바꿔요.
- 스페이스 후보 바꾸기는 `⇧Tab`이에요(Windows `Shift+Tab`). 후보는 위 순서의 모든 일치와 마지막에 ‘스페이스 없음’이에요.
- 이 키가 이미 쓰이고 있으면 두 앱이 정해서 아래 ‘정한 것’에 적어요.

**한 스페이스만 보기 중**
- `#`가 없으면 그 스페이스에 넣어요.
- `#`가 있으면 `#`가 이겨요(S8).

## 3. 한 스페이스만 보기

**고르기**
- 오늘 탭 머리말 오른쪽의 `모든 스페이스 ▾`로 골라요. 스페이스가 0개면 이 버튼은 숨겨요.
- 단축키는 Mac `⌘⌥1`–`⌘⌥9`(스페이스 순서), `⌘⌥0`은 모두 보기예요.
- Windows는 `Ctrl+Alt+숫자`가 AltGr 배열(독일어 `AltGr+7` = `{`, 폴란드어 등)과 부딪혀요. 그래서 다른 키를 정해 ‘정한 것’에 적어요. 후보는 `Ctrl+Shift+1–9`이고, 이미 쓰이고 있는지 확인해요.

**거른 동안**
- 오늘 탭에는 그 스페이스의 할 일만 보여요(다음 · 그 밖에 구성 그대로).
- 위에 띠: `회사만 보는 중 · 다른 할 일 N개는 숨겼어요 · 모두 보기`
  - N은 숨긴 할 일 중 **끝내지 않은 것**의 수예요.
  - N = 0이면 `회사만 보는 중 · 모두 보기`예요.
- 입력 줄 안내는 `회사에 적어요 — 할 일, 일정…`이에요.
- 오늘 탭의 숫자 배지는 **모든** 할 일 수 그대로예요. 숨긴 것도 셈이 보여야 놓치지 않아요.
- 알림 · 알람 · 고양이는 그대로예요. 거르기는 보기만 바꿔요.

**풀리는 때**
- 4시 규칙의 날짜가 바뀌면(앱이 켜진 채 넘어가도) 풀려요.
- 그 스페이스가 지워지면 풀려요.
- `모두 보기` 또는 `⌘⌥0`을 눌러도 풀려요.

## 4. 표시와 옮기기

**색 띠**
- 오늘 탭의 할 일 줄 왼쪽 끝에 폭 4pt(Windows 4px), 높이는 줄 높이의 약 55%, 오른쪽 모서리만 둥근 띠를 그려요.
- 색은 스페이스 색의 진한 쪽(대비 3:1 이상, 종이 위)이에요.
- 마우스를 올리면 스페이스 이름 툴팁이 떠요.
- 끝낸 할 일은 흐리게 그려요(투명도는 줄 글자와 같게).

**우클릭 메뉴**
- 할 일 줄 우클릭 메뉴에 `스페이스로 옮기기 ▸`를 더해요.
  - 하위 메뉴: 스페이스 목록(색 · 이름, 지금 것은 ✓) → 구분선 → `스페이스 없음` → `새 스페이스…`
  - `새 스페이스…`: 이름을 받는 작은 쪽지예요. 만들고 바로 그 할 일을 옮겨요.
- 우클릭 메뉴가 아직 없으면 1.44 메모 서랍 메뉴와 같은 방식으로 만들어요.
  - Mac은 NSMenu예요.
  - Windows는 `drawerMenu.ts`와 같은 컴포넌트를 쓰고, `Shift+F10` · 메뉴 키로도 열려요.

**옮긴 뒤**
- 토스트 `회사로 옮겼어요 · 되돌리기`가 떠요.
- 거르는 중에 다른 스페이스로 옮기면 그 줄은 목록에서 빠지고, 띠의 N이 늘어요.

**할 일 고치기 쪽지**
- 마감 · 시간 칸 근처에 `스페이스` 칸(팝업)을 둬요.

**책상 → 스페이스 칸**
- 자리: 메모 서랍 칸 다음이에요. 숫자 단축키는 없어요(AI 연결처럼).
- 목록: 끌어서 순서 바꾸기, 이름(바로 고치기), 8색, 지우기(`스페이스 ‘회사’를 지웠어요 · 되돌리기`, 할 일은 ‘스페이스 없음’으로), `+ 새 스페이스`.
- 아래 설명: `할 일을 회사 · 집처럼 나눠요. 오늘 한 장에는 그대로 모두 보이고, 머리말에서 한 스페이스만 볼 수 있어요. 입력 줄에 #이름을 붙이면 그 스페이스로 들어가요.`

**`모든 스페이스 ▾` 팝업**
- 첫 줄 `모든 스페이스 (N)`, 구분선, 스페이스 목록(색 · 이름 · 끝내지 않은 할 일 수 · 단축키), `스페이스 없음 (N)`, 구분선, `스페이스 관리…`(책상 칸 열기)예요.
- `스페이스 없음`도 고를 수 있어요. 스페이스가 없는 할 일만 보여 줘요.

## 5. 말 (ko 기준. en · nl은 두 앱이 함께 정해 ‘정한 것’에 적어요)

스페이스 · 모든 스페이스 · 스페이스 없음 · 스페이스로 옮기기 · 새 스페이스… · 새 스페이스 ‘%@’ · 스페이스 관리… · %@만 보는 중 · 다른 할 일 %d개는 숨겼어요 · 모두 보기 · %@에 적어요 — 할 일, 일정… · %@(으)로 옮겼어요 · 스페이스 ‘%@’를 지웠어요 · 되돌리기.

조사는 이름의 받침에 따라 붙여요(회사로 / 집으로, 회사를 / 집을). 앱에 이미 있는 조사 함수가 있으면 그걸 써요.

## 6. 공유 사례 (두 앱 같은 입력, 같은 기대값)

준비: 스페이스 회사(s-a) · 집(s-b) · 공부(s-c) 순서, A업무(s-d, 이름에 공백 없음)는 나중에 만들어요.

| # | 입력 · 상황 | 기대 |
| --- | --- | --- |
| S1 | `견적서 보내기 #회사` | 할 일 ‘견적서 보내기’, 회사 |
| S2 | `견적서 #회` | 회사(앞부분) |
| S3 | `견적서 #ㅎㅅ` | 회사(초성) |
| S4 | `빨래 #세탁` (없음) | 새 스페이스 ‘세탁’(다음 색), 할 일 ‘빨래’ |
| S5 | `#회사` | 넣지 않음(제목 없음) |
| S6 | `C# 공부`, `이슈 #12 확인`, `a#b` | 토큰 아님, 제목 그대로, 스페이스 없음 |
| S7 | 회사만 보는 중, `보고서` | 회사 |
| S8 | 회사만 보는 중, `빨래 #집` | 집 |
| S9 | `내일 3시 회의 #회사` | 일정, 제목 ‘회의’, 스페이스 없음, 토큰 빠짐 |
| S10 | `보고서 #회사 #집` | 회사, 제목 ‘보고서 #집’ |
| S11 | 보기 상태 day=10-27, 지금 10-28 03:59 / 04:00 | 03:59는 유지, 04:00은 풀림 |
| S12 | 회사를 지움 → 회사 할 일 | 스페이스 없음, 보기 풀림, 파일에는 자리 그대로 |
| S13 | 기기 A: 할 일 X → 회사 at 10:00, 기기 B: X → 집 at 10:05 | 집 |
| S14 | A: X → 없음(null) 10:05, B: X → 회사 10:00 | 없음 |
| S15 | 회사 이름 A가 10:00에 ‘업무’, B가 10:02에 ‘직장’ | ‘직장’ |
| S16 | 모르는 키(맨 위 `series`, 스페이스 `icon`, 자리 `pin`) | 읽고 쓴 뒤 바이트 그대로 |
| S17 | todos.json에 없는 할 일의 자리, at 31일 전 / 29일 전 | 31일 전은 저장 때 빠짐, 29일 전은 남음 |
| S18 | 백업 내보내기 → 가져오기(합치기) | S13 · S14 규칙으로 합쳐짐 |
| S19 | 스페이스 0개 | 버튼 · 띠 · 칩 없음, 화면 그대로(스냅숏 1.44와 같음) |
| S20 | 이름 `A 업무`, 입력 `#A업무` / `#a` | 둘 다 A 업무 (공백 무시 · 대소문자 무시) |
| S21 | 읽지 못하는 파일 | `.unreadable-*`로 옆에 두고 빈 상태 |
| S22 | 지운 지 31일 된 스페이스 | 저장 때 빠짐 |

## 7. 점검과 성능

- **두 앱 모두**: S1–S22 자동 검사, 기존 검사 전부 통과, ko · en · nl 번역 검사.
- **대비**: 색 띠 8색 × 낮 · 밤 종이에서 3:1 이상.
- **스냅숏 (ko · en · nl, 낮 · 밤)**
  - 오늘 탭: 스페이스 0개(1.44와 같아야 함), 섞인 한 장, 회사만 보는 중(띠)
  - 입력 줄 `#회사` 칩, 새 스페이스 칩
  - `모든 스페이스 ▾` 팝업, 우클릭 → 스페이스로 옮기기
  - 책상 스페이스 칸, 고치기 쪽지
- **성능**
  - 할 일 2,000개 + 스페이스 9개에서 노트 열기 · 오늘 탭 그리기 · 거르기 바꾸기 · 입력 줄 타이핑을 1.44와 번갈아 재요.
  - 오늘 탭 그리기는 1.44 대비 +10% 이내, 타이핑은 같아야 해요.
  - 쉴 때 CPU는 그대로예요. 스페이스 기능에는 타이머를 쓰지 않아요. 날짜 바뀜은 이미 있는 하루 바뀜 알림에 붙여요.
- **README · 도움말 · CHANGELOG**: 두 앱의 도움말에 ‘스페이스’ 주제를 둬요. CHANGELOG는 Mac 1.45.0 · Windows 1.30.0 항목이에요. README에는 스페이스 줄을 더해요.
- **예시 데이터**: 실제 메모 · 전화번호 · 회사 이름을 쓰지 않아요. 예시 스페이스는 ‘회사 · 집 · 공부’처럼 일반 단어예요.

## 정한 것 (구현 중)

(두 앱이 여기에 적어요)

### Windows (1.30.0)에서 정한 것

**W1. `todos.json`은 모르는 키를 지워요 (확인함).** Windows ≤ 1.29의 `parseNotebook`은 아는 키만 골라 읽고, `serializeNotebook`은 읽은 것만 써요. 그래서 할 일에 `space` 키를 더하면 옛 버전이 한 번 저장할 때 사라져요. 기획의 ADR대로 `todo-spaces.json`에 따로 둬요. (검사: `todoSpaces.test.ts`의 ‘todos.json drops unknown keys’)

**W2. 파일의 바이트.** 두 앱이 같은 상태에서 같은 바이트를 쓰도록 이렇게 정해요.
- 모든 객체를 **완전히 펼친** 모양이에요. `JSON.stringify(값, null, 2)`와 같아요: 들여쓰기 2칸, `"키": 값`(쌍점 뒤 공백 하나, 앞에는 없음), 원소마다 한 줄, 빈 배열은 `[]`, 빈 객체는 `{}`, 끝에 줄바꿈 하나.
- 키는 모든 깊이에서 정렬해요(UTF-8 바이트 순서). 맨 위는 `items` · `spaces` · `version`, 스페이스는 `color` · `deleted` · `id` · `name` · `order` · `updatedAt`, 자리는 `at` · `space`이고, 모르는 키도 그 사이에 정렬해 들어가요.
- `spaces` 배열은 `order`, 같으면 `id` 순서예요. `items`는 할 일 id(키) 순서예요.
- `deleted`는 `true`일 때만 써요. `"space": null`은 그대로 `null`로 써요.
- 문자열은 `"` · `\` · 제어 문자만 이스케이프해요. `\n` `\r` `\t`는 그 이름으로, 나머지 제어 문자는 `\u00xx`(소문자 16진)로 써요. 한글 등 ASCII 밖의 글자와 `/`는 그대로 써요(1.44 `memo-folders.json`과 같은 규칙).
- 시각은 읽을 때 날짜로 읽고 쓸 때 `yyyy-MM-ddTHH:mm:ssZ`(UTC, 초 단위)로 써요. 읽지 못하는 시각은 `1970-01-01T00:00:00Z`예요.
- 숫자(`order`, 모르는 키의 값)는 정수면 정수 그대로, 아니면 가장 짧은 십진 표기예요.
- 예:
  ```
  {
    "items": {
      "6F1C…": {
        "at": "2026-10-28T09:01:00Z",
        "space": "s-7f3a9c"
      }
    },
    "spaces": [
      {
        "color": "pink",
        "id": "s-7f3a9c",
        "name": "회사",
        "order": 0,
        "updatedAt": "2026-10-28T09:00:00Z"
      }
    ],
    "version": 1
  }
  ```
- Mac의 `JSONSerialization` `.prettyPrinted`는 `"키" : 값`(쌍점 앞에도 공백)과 빈 객체 `{\n\n}`을 써서 바이트가 달라요. 직접 쓰는 함수가 필요해요.

**W3. 합치기의 ‘같은 시각’.** `merge(이미 있는 것, 들어온 것)`에서 들어온 쪽은 **더 늦을 때만** 이겨요. 공유 폴더에서 다른 기기의 저장을 읽을 때는 디스크의 파일이 ‘이미 있는 것’, 이 기기의 것이 ‘들어온 것’이에요. 백업 가져오기(합치기)에서는 이 기기의 파일이 ‘이미 있는 것’, 백업이 ‘들어온 것’이에요. 맨 위의 모르는 키는 이미 있는 쪽을 먼저 두고, 없는 키만 들어온 쪽에서 더해요.

**W4. 정리(30일).** 저장할 때만 해요. 자리: 할 일이 `todos.json`에 없고 `at`이 지금보다 30일(30 × 24시간)을 **넘게** 지났으면 빼요(S17: 31일 전은 빠지고 29일 전은 남아요). 지운 스페이스: `updatedAt`이 30일을 넘게 지났으면 빼요(S22). 정확히 30일은 남겨요.

**W5. `#` 토큰.**
- `#` 앞이 줄의 시작이거나 공백(스페이스 · 탭)이고, `#` 뒤로 공백이 아닌 글자가 이어지는 동안이 토큰이에요. 문장 부호도 토큰에 들어가요(`#회사,`는 ‘회사,’).
- 숫자로만 된 것(`#1`, `#2024`)과 `#` 바로 뒤가 또 `#`인 것(`##제목`)은 토큰이 아니에요. 토큰이 아닌 것은 건너뛰고 그다음 토큰을 봐요(`이슈 #12 확인 #회사` → 회사).
- 여러 줄 입력(메모)은 첫 줄만 봐요.
- 이름 비교는 NFC로 맞춘 뒤 소문자로 바꾸고 모든 공백을 지워서 해요.
- 초성 비교에서 이름의 한글 음절은 초성으로, 그 밖의 글자는 그대로(소문자) 둬요. 토큰은 ㄱ–ㅎ 호환 자모로만 돼 있어야 해요. 쌍자음(ㄲ ㄸ ㅃ ㅆ ㅉ)은 그 글자 그대로예요.
- 후보 순서: 이름 전체가 같은 것 → 앞부분이 같은 것(스페이스 순서) → 초성이 같은 것(스페이스 순서), 겹치면 한 번만. 일치가 없으면 `새 스페이스 ‘토큰’` 하나예요. 맨 끝에 늘 `스페이스 없음`이 붙어요.

**W6. 새 스페이스의 색.** 8색 순서(`lavender pink mint yellow sky peach sand gray`)에서 살아 있는 스페이스가 아직 쓰지 않은 첫 색이에요. 8색을 다 쓰고 있으면 `살아 있는 스페이스 수 % 8`번째 색이에요. 새 스페이스의 `order`는 살아 있는 것 중 가장 큰 `order` + 1(없으면 0)이에요. 이름은 줄바꿈을 공백으로 바꾸고 앞뒤 공백을 뺀 40자까지예요(메모 폴더와 같아요).

**W7. `⇧Tab`은 이미 입력 줄에서 ‘뜻을 거꾸로 바꾸기’로 쓰여요(두 앱 모두).** 그래서 줄에 `#` 토큰이 있을 때만 `⇧Tab`이 스페이스 후보를 바꾸고, 토큰이 없으면 지금처럼 뜻을 거꾸로 바꿔요. 스페이스 칩을 눌러도 다음 후보로 바뀌어요.

**W8. Windows의 한 스페이스만 보기 단축키는 `Ctrl+Shift+1`–`9`, 모두 보기는 `Ctrl+Shift+0`이에요.**
- `Ctrl+Alt+숫자`는 AltGr 배열에서 글자를 치는 키라(AltGr = Ctrl+Alt) 쓰지 않아요.
- 확인한 것: 앱 메뉴(`Ctrl+1` · `Ctrl+2` · `Ctrl+Shift+C` · …), 노트의 키(`Ctrl+Shift+N` · `Ctrl+Shift+C`), 전역 단축키(`Ctrl+Alt+M · J · N`, 메모 서랍 `Ctrl+Shift+D`) 어디에도 `Ctrl+Shift+숫자`가 없어요. 메모 서랍 안의 `Ctrl+1–9`는 서랍 창의 키라 겹치지 않아요.
- 키는 `event.code`(`Digit1`…)로 읽어요. 그래서 Shift를 누르면 `!`가 되는 배열이나 AZERTY(숫자 줄이 기호)에서도 같아요. 숫자 패드는 쓰지 않아요.
- 남는 걱정: Windows 입력 언어 전환 단축키를 `Ctrl+Shift`로 바꾼 PC에서는 `Ctrl+Shift+0`이 시스템에 먼저 갈 수 있어요. 띠의 `모두 보기`와 팝업은 늘 돼요. 메모 서랍 단축키를 사용자가 `Ctrl+Shift+숫자`로 바꾸면 그 키는 서랍이 가져가요.
- 노트 창에 포커스가 있을 때만 돼요(전역 단축키가 아니에요). 팝업과 도움말에는 `Ctrl+Shift+1`처럼 보여요.

**W9. 기기 설정.** 보기 상태는 `settings.json`의 `prefs.spaceLens = { "spaceId": "s-…" | "none", "day": "yyyy-MM-dd" }`이고, 없으면 모두 보기예요. `"none"`은 ‘스페이스 없음’만 보기예요. 날짜 바뀜은 이미 있는 4시 규칙의 하루 바뀜(`newDayOnNote`)과 상태를 그릴 때 확인해요(따로 타이머 없음).

**W10. 셈.** `모든 스페이스 ▾` 팝업의 숫자는 오늘 탭의 끝내지 않은 할 일 수예요(`모든 스페이스 (N)`도). 띠의 N은 오늘 탭에서 숨긴 것 중 끝내지 않은 것이에요.

**W11. ‘스페이스 없음’만 보기의 말.** 머리말 버튼 `스페이스 없음 ▾`, 띠 `스페이스 없는 할 일만 보는 중 · 다른 할 일 N개는 숨겼어요 · 모두 보기`, 입력 줄 안내는 평소 그대로예요(넣으면 스페이스 없음). 이때 머리말 버튼에는 `만`을 붙이지 않아요. 스페이스 하나를 볼 때 버튼은 시안처럼 `회사만 ▾`이에요.

**W12. 말 (en · nl).** 조사: 받침 없음 또는 ㄹ받침 → `로`, 그 밖의 받침 → `으로`. `를`/`을`은 받침으로. 영문 · 숫자로 끝나면 읽는 소리로(메모 서랍의 `은/는`과 같은 규칙).

### Mac (1.45.0)에서 정한 것

**M1. W1–W12를 그대로 따라요.** Mac ≤ 1.44의 `todos.json`도 Codable이라 모르는 키를 지워요(W1과 같은 이유). 파일의 바이트(W2)는 Mac이 직접 써요(`KeptJSON.pretty`). 키 정렬은 유니코드 코드 포인트 순서(= UTF-8 바이트 순서)예요.

**M2. 스페이스가 0개면 `#`를 읽지 않아요(S19).** 칩도 `새 스페이스`도 없고, 제목은 적은 그대로예요(`빨래 #세탁` → 할 일 ‘빨래 #세탁’). 기획의 ‘스페이스를 하나도 만들지 않은 사람에게는 아무것도 바뀌지 않아요’를 따라요. 첫 스페이스는 책상 → 스페이스 칸이나 할 일 우클릭 → `새 스페이스…`로 만들어요. *(Windows도 같아요(W13). `spaces-cases.json`의 S19 줄이 이 사례예요.)*

**M3. `스페이스 없음`을 고르고 넣어도 토큰은 제목에서 빠져요**(§2 ‘넣을 때’ 그대로).

**M4. 스페이스 칩은 고른 뜻이 할 일일 때만 보여요.** 일정 · 타이머 · 알람 · 메모를 고르면 칩이 숨어요(토큰은 빠져요, S9). 반복 할 일(`매일 물 마시기 #집`)도 1단계에서는 스페이스를 붙이지 않아요. 반복 규칙의 스페이스는 2단계예요.

**M5. 거르는 중 `#`가 없으면** 칩은 `● 회사` 하나예요(W와 같아요, 후보에 ‘스페이스 없음’ 없음). `⇧Tab`은 토큰이 없으니 지금처럼 뜻을 거꾸로 바꿔요(W7).

**M6. `items`의 키는 `todos.json`의 할 일 id 그대로예요.** 두 앱 모두 대문자 UUID(`UUID().uuidString`, `randomUUID().toUpperCase()`)예요.

**M7. 지우기 · 되돌리기.** 지우기는 지운 표시만 하고 자리는 그대로예요(S12). 되돌리기는 지운 표시를 걷고(`updatedAt` 지금), 그 스페이스에 있던 할 일의 자리를 다시 그 스페이스로 써요(`at` 지금). Windows의 `deleteSpace` · `restoreSpace`와 같아요.

**M8. 읽지 못한 파일의 이름**은 `todo-spaces.json.unreadable-20261028-090000`(UTC `yyyyMMdd-HHmmss`)이에요. 옆으로 옮기고 한 번 알려요.

**M9. 공유 사례 데이터 `docs/plans/spaces-cases.json`.** S1–S22를 데이터로 적었어요. `lines`(입력 → 뜻 · 제목 · 스페이스 · 후보), `lens`(보기 상태 → 보이는 것, `null`은 모두), `merges` · `renames`(합치기, 양쪽 방향), `S16`(모르는 키가 든 정본 파일. 읽고 쓰면 바이트가 같아야 해요), `prune`(S17 · S22, 정확히 30일은 남아요), `unreadable` · `readable`(S21). 시각은 UTC, `timeZone`은 `Asia/Seoul`, 지금은 10월 28일 10:00(KST)이에요. Mac은 `mac/scripts/test-spaces.sh`가 이 파일을 읽어요. Windows도 같은 파일을 읽으면 두 앱이 어긋날 수 없어요. 후보의 표기는 스페이스 id, `new:<이름>`, `none`이에요.

**M10. 조사.** W12와 같되, 끝 글자가 숫자 · 영문일 때 읽는 소리를 이렇게 봐요. `1 7 8 l r` → ㄹ받침(`로` · `을`), `0 3 6 m n` → 다른 받침(`으로` · `을`), 그 밖 → 받침 없음(`로` · `를`). 0은 ‘영’, r은 ‘알’이에요. *(Windows도 W13에서 맞췄어요.)*

**M11. 색 띠의 색**(스페이스 색의 진한 쪽). 낮 종이 `#fbf9f3`, 밤 종이 `#2a2924`에서 모두 3:1을 넘어요(`check-contrast.py`가 8색 × 낮 · 밤 · 카드를 검사해요). Windows도 같은 값을 쓰면 두 앱의 띠가 같아요.

**M12. **M13. `되돌리기`의 nl은 Mac 앱 전체가 이미 쓰는 `Herstel`이에요.** (Windows 앱 전체는 `Ongedaan maken`. 1.45 전부터 달랐고, 스페이스만 바꾸지 않아요.)

**M14. 날짜 바뀜.** 새 타이머는 없어요. 보기 상태는 그릴 때마다 `SpaceLens.shown`으로 4시 규칙의 날짜를 확인하고, 앱이 이미 가진 하루 바뀜(오늘 목록을 다시 셈하는 4시 경계)과 창이 다시 앞에 올 때 다시 그려요.

### Windows (1.30.0)에서 더 정한 것 (M1–M14를 읽고)

**W13. M2 · M10 · M11에 맞췄어요.** 스페이스가 0개면 `#`를 읽지 않아요(Windows는 처음부터 그랬고, `spaces-cases.json`의 S19 줄로 검사해요). 조사는 M10의 숫자 · 영문 읽기(`1 7 8 l r` → ㄹ, `0 3 6 m n` → 다른 받침)로 고쳤어요. 띠 색은 M11의 표를 그대로 써요(Windows의 종이 · paper-2 · 카드에서도 모두 3:1 이상, 낮 가장 낮은 값 3.09). M13의 nl `Herstel`은 따르지 않고 Windows 앱 전체가 쓰는 `Ongedaan maken` 그대로예요.

**W14. 공유 사례 파일을 Windows도 읽어요.** `windows/test/todoSpaces.test.ts`가 `docs/plans/spaces-cases.json`의 `lines` · `lens` · `merges` · `renames` · `S16` · `prune` · `unreadable` · `readable`을 모두 돌려요(S1–S22 각 사례의 검사와 따로).

**W15. 거르기의 입력 기본값은 노트의 입력 줄에만 있어요.** 빠른 입력(`Ctrl+Alt+N`)과 오늘 창의 입력 줄은 `#`는 읽지만 보기 상태는 따르지 않아요(그 창들은 거른 목록을 보여 주지 않으니까요). Mac이 빠른 입력에도 보기 상태를 쓰면 알려 주세요.

**W16. 할 일 메뉴는 종이 메뉴예요(Windows).** Windows의 할 일 우클릭 메뉴는 1.29까지 Electron 기본 메뉴였어요. 1.30부터 메모 서랍과 같은 `drawerMenu` 컴포넌트로 노트 안에 그려요. 항목(이거 집중 ▸ · 고치기 · … · 지우기)은 그대로이고, `완료 표시` 아래에 `스페이스로 옮기기 ▸`가 생겨요(스페이스가 하나라도 있을 때만). 줄을 고른 뒤 `Shift+F10` · 메뉴 키로도 열려요. 하루 띠의 할 일 우클릭도 같은 메뉴예요.

**W17. `새 스페이스…`(우클릭 하위 메뉴)는 메뉴 안의 이름 칸이에요.** 이름을 적고 Enter(또는 ‘만들고 옮기기’)면 다음 색(W6)으로 만들고 그 할 일을 옮겨요. 입력 줄의 `#세탁`으로 생긴 스페이스는 그 할 일을 되돌리면(토스트의 되돌리기 · `Ctrl+Z`) 함께 지워져요(지운 표시).

**W18. 할 일 고치기 쪽지의 스페이스 칸은 고르는 즉시 옮겨요.** 쪽지의 알림 · 반복 · 마감 · 시간 탭은 저장 단추가 각자인데, 스페이스는 탭과 상관없는 칸이라 고르면 바로 옮기고 토스트를 띄워요. 이 칸의 메뉴에는 `새 스페이스…`를 두지 않았어요.

**W19. 머리말 버튼의 자리(Windows).** Windows 노트는 제목 줄 오른쪽에 고양이가 있어서, `모든 스페이스 ▾`를 날짜 줄 끝(제목 위)에 뒀어요. 그래서 스페이스가 생겨도 머리말 높이와 제목의 자리가 1.29와 같아요. 스페이스 하나를 볼 때 버튼은 `회사만 ▾`(그 색 테두리), ‘스페이스 없음’을 볼 때는 `스페이스 없음 ▾`이에요.

**W20. 할 일이 자리 없이 ‘스페이스 없음’으로 옮겨지면 아무것도 쓰지 않아요.** 처음부터 스페이스가 없던 할 일에 `스페이스 없음`을 고르면 파일이 바뀌지 않아요(`null` 자리는 스페이스에 있다가 옮겼을 때만 생겨요).

**W21. 공유 폴더에서 읽을 때의 합치기.** 다른 기기가 쓴 `todo-spaces.json`이 들어오면 `merge(디스크의 것, 이 기기의 것)`(W3)이고, 정리(W4)는 이 기기가 쓸 때만 해요. 읽지 못하는 파일은 세 번 다시 읽어 본 뒤 옆으로 옮기고 이 기기의 것을 써요(1.28 메모 서랍과 같아요).

### Mac (1.45.0)에서 더 정한 것 (W13–W21을 읽고)

**M15. 입력 줄 안내가 길면** `회사에 적어요`로 줄여요(긴 말이 입력 칸에 다 들어가지 않을 때, en `Writing in Work`, nl `Schrijf in Werk`).

**M16. 보기 상태를 따르는 입력은 W15에 맞췄어요.** 노트의 오늘 탭 입력 줄만 `#`가 없을 때 보고 있는 스페이스에 넣어요. 빠른 입력(`⌃⌥N`), 앞으로 탭 입력 줄, 메뉴 막대 오늘 창은 `#`만 읽어요.

**M17. `⇧Tab` 안내 칩.** 토큰이 있으면 `⇧Tab`은 늘 스페이스를 바꾸지만(W7), 줄 위의 `⇧Tab` 안내 칩은 맞는 스페이스가 둘 이상일 때만 보여요(`회사`와 `스페이스 없음`뿐이면 칩이 줄을 하나 더 차지해서요).

**M18. 거르기를 바꿀 때는 줄 움직임 없이 바로 바꿔요.** 할 일 2,000개에서 오늘 탭의 줄 애니메이션이 1,800줄이 들고 나는 것을 비교하느라 몇 초씩 걸렸어요(perf.sh `--spaces`). 바꾼 뒤 그리기는 100–270ms예요.

**M19. `⇧Return`(적은 그대로)** 은 `#`도 글자로 남기고 스페이스를 붙이지 않아요. 거르는 중이면 그 스페이스에 넣어요.

**M20. 큰 수는 자리를 나눠요.** 띠의 N과 팝업의 수: `1,466`(ko · en) · `1.466`(nl), 탭의 수와 같아요.

**M21. 시각을 직접 읽고 써요.** `yyyy-MM-ddTHH:mm:ssZ`는 손으로 읽고(그 밖의 모양만 ISO 형식기로), 쓸 때도 직접 써요. 할 일 2,000개의 파일을 열 때 항목마다 형식기를 만드느라 노트가 300ms 늦게 떴어요. Windows는 `Date.parse`라 해당 없어요.

**M22. `새 스페이스…`의 쪽지**는 제목 `새 스페이스`, 안내 `스페이스 이름`, 빈칸 `회사, 집, 공부…`, 단추 `취소` · `만들기`예요(색은 W6). 책상 칸의 `+ 새 스페이스`도 같은 쪽지예요.

**M23. 스페이스가 0개일 때 메뉴는 W16에 맞췄어요.** 우클릭 `스페이스로 옮기기 ▸`는 스페이스가 하나라도 있을 때만 있어요(S19). 첫 스페이스는 책상 → 스페이스의 `+ 새 스페이스`로 만들어요. 고치기 쪽지의 스페이스 칸과 머리말 버튼도 0개면 없어요.

**M24. 할 일 고치기 쪽지의 칸 이름**은 하나라서 en `Space` · nl `Ruimte`, 책상 칸 · 도움말 주제는 `Spaces` · `Ruimtes`예요.

**M25. W18 · W20 · W21에 맞췄어요.** 고치기 쪽지의 스페이스 칸은 고르는 즉시 옮기고(토스트), 그 메뉴에는 `새 스페이스…`가 없어요. 자리 없는 할 일을 ‘스페이스 없음’으로 옮기면 아무것도 쓰지 않아요. 다른 기기의 파일을 읽지 못하면 다음 확인(2초마다)에 다시 읽고, 세 번째에 옆으로 옮겨요.

**M26. 머리말 버튼의 자리(Mac).** Mac 노트는 제목 오른쪽, 엿보는 고양이 앞에 둬요(시안의 자리). 머리말 높이는 그대로이고, 제목 옆 `1/7 끝냈어요`가 들어가지 않는 폭에서는 1.44처럼 제목 아래로 내려가요. 좁으면 버튼은 색 점과 ▾만 남아요. *(Windows W19는 날짜 줄 끝. 두 앱의 노트 머리말 모양이 달라서 자리도 달라요.)*

**M27. `새 스페이스…`는 Mac에서 쪽지예요(M22).** Windows W17은 메뉴 안의 이름 칸이에요. 하는 일(이름 → 다음 색으로 만들고 그 할 일을 옮김)과 말은 같아요. 입력 줄이 만든 스페이스는 그 할 일을 되돌리면(토스트의 되돌리기 · `⌘Z`) 그 안에 다른 할 일이 없을 때 함께 지워져요(W17과 같아요).
