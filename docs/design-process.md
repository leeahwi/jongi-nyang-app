# 디자인 과정

[← 저장소로](../README.md) · [구조](architecture.md) · [엔지니어링](engineering.md) · [결정 기록](decisions.md)

화면은 여러 번 바뀌었다. 매번 안을 받아 고르고, 만들고, 두 앱의 스냅숏을 나란히 놓고 고쳤다. 아래 그림은 모두 그 시기의 실제 앱을 그린 것이다(날짜 표시는 가렸다).

## 일하는 순서

```mermaid
flowchart LR
    P["제안<br/>여러 안을 한 페이지에 나란히"] --> C["고르기<br/>안을 고르거나 섞고,<br/>버릴 것을 정함"]
    C --> S["사양 + 사례 표<br/>말, 숫자, 상태를 먼저 적음"]
    S --> B1["Mac 구현"]
    S --> B2["Windows 구현"]
    B1 --> R["스냅숏을 나란히<br/>낮/밤, 3개 언어, 크기별"]
    B2 --> R
    R -->|다른 곳, 깨진 곳| S
```

AI가 만든 제안은 여러 안을 나란히 놓은 HTML 페이지로 받았다(작업 폴더에서만 썼고 이 저장소에는 없다). 어느 안을 쓸지, 섞을지, 버릴지는 내가 정했다.

매일 쓰면서 고를 때의 기준은 거의 하나였다. 한눈에 알아볼 수 있는가. 타이머와 알람은 시간이 또렷이 보여야 하지만, 내 화면 위에 늘 떠 있으니 크기와 모양이 일을 방해하지 않아야 했다.

고른 안은 화면을 만들기 전에 말과 숫자로 적었다. 어떤 글이 어디에 몇 줄 들어가는지, 몇 분 전부터 붉게 바뀌는지, 좁은 창에서는 무엇을 줄이는지. 이 표가 그대로 [공유 시험 사례](engineering.md#1-공유-시험-사례)가 됐다.

## 처음 정한 원칙 (Mac 1.5, 1.10)

Things와 Bear의 공식 화면, Apple HIG의 알림과 팝오버 항목을 보고 이 앱에 맞는 것만 가져왔다.

- 할 일이 중심이고, 보조 정보와 편집은 필요한 자리에서만 보인다.
- 모든 줄은 44pt 높이. 줄 끝 정보는 평소엔 흐린 글자이고, 마우스를 올리면 버튼이 된다.
- 같은 때 울릴 알림은 말풍선 하나로 모은다(HIG의 "같은 일로 여러 번 알리지 않기").
- 종이 질감은 옅게, 글자 대비는 높게. 시스템의 움직임 줄이기 설정을 따른다.

## 새 디자인: 3차 개편안을 네 단계로

개편안은 여러 번 고쳐 썼고, 세 번째 안을 네 단계로 나눠 두 앱에 넣었다. 단계마다 Mac과 Windows가 같은 화면이 되게 버전을 맞췄다.

| 단계 | Mac, Windows | 들어간 것 |
| --- | --- | --- |
| 1 | 1.34.0, 1.19.0 | 입력 줄과 칩, 하루 띠, 쪽지 모달, 색 토큰 |
| 2 | 1.35.0, 1.20.0 | 앞으로 탭(마감과 나중에를 합침), 오늘 창 |
| 3 | 1.36.0, 1.21.0 | 책상 창(창 네 개를 하나로), 밤 종이 |
| 4 | 1.37.0, 1.22.0 | 집중 모드, 낮 종이 WCAG AA |
| 점검 | 1.37.1, 1.22.1 | 두 앱을 화면마다 나란히 놓고 고친 판 |

### 입력 줄

할 일, 일정, 타이머, 알람, 메모를 만드는 곳이 다섯 군데였다. 개편안은 이것을 맨 아래 한 줄로 모았다.

![입력 줄과 칩](screenshots/mac/line-event.png)

적는 동안 줄 위의 칩이 알아들은 뜻을 보여 주고, 틀렸으면 `Tab`으로 바꾼다. 넣은 뒤 뜨는 안내의 '바꾸기'를 누르면 방금 넣은 것을 지우고 다른 뜻으로 다시 넣는다. 같은 말을 두 번 바꾸면 다음부터는 그 뜻이 먼저 나온다.

가장 중요하게 본 건 잘못 알아들어도 한 번에 고칠 수 있느냐였다. 그래서 알아듣는 규칙은 넓게 잡고, 되돌리기는 항상 한 번으로 했다.

### 쪽지 모달

떠 있는 창마다 모양이 달랐다(시스템 경고창, 설정 창, 알람 카드…). 개편안은 이것을 테이프로 붙인 종이 쪽지 한 종류로 묶었다.

![알람: 전후](screenshots/process/modal-alarm-before-after.png)

![일정 쪽지: 전후](screenshots/process/modal-event-before-after.png)

| 부분 | 규칙 |
| --- | --- |
| 종이 | 종이색, 모서리 16, 그림자 하나. 나타날 때 8pt 떠오르며 바로 선다. |
| 테이프 | 윗변 가운데 와시 테이프. 색이 종류를 나타낸다: 할 일 꿀색, 메모 라벤더, 일정 하늘색, 타이머 민트, 알람과 알림 장미색, 확인 무채색. |
| 머리 | 28pt 둥근 배지, 제목, 흐린 맥락, × |
| 칸 | 적는 칸은 손글씨 밑줄, 고르는 칸은 칩. 이름표 열은 없앴다. |
| 바닥 | 왼쪽에 키 안내, 오른쪽에 세이지색 확인 단추 하나(단축키는 단추 안에) |
| 위험한 동작 | 지우기와 바꾸기는 왼쪽 아래 점토색. Return으로 눌리지 않는다. |

울리는 알람 쪽지의 모양은 `AlarmRingSlip.swift` 한 파일에 모아서 다른 안으로 바꿔 보기 쉽게 했다.

이 규칙을 만든 뒤에도 실수가 나왔다. Mac 1.40.1에서 집중 카드의 ×를 누르면 "그만둘까요?" 확인 쪽지가 크기 0으로 떠서 보이지 않았고, 그동안 앱 전체가 클릭을 받지 않았다. 확인 쪽지가 누른 동작이 끝나기 전에 뜨면서 크기를 재지 못한 것이다. 이제 확인 쪽지는 누른 동작이 끝난 뒤 뜨고, 크기를 재지 못하면 임시 크기로 먼저 그린다.

### 하루 띠: 세 번 다시 그렸다

오늘 일정을 할 일 목록 위에 어떻게 보여 줄지에 시간을 가장 많이 썼다.

1차 (Mac 1.34, Windows 1.19). '오늘 일정' 카드 대신 하루를 막대 한 줄로 그렸다. 일정은 색 막대, 할 일 알림은 막대 아래 작은 고리, 지금은 숨 쉬듯 깜빡이는 선이고, 아래에 '지금 팀 회의 → 40분 뒤 19:32 치과' 같은 문장 하나를 두었다.

![하루 띠 1차](screenshots/process/daystrip-round1.png)

2차 (Mac 1.37.1–1.39, Windows 1.22.1–1.24). 눈금을 6시간 단위로 바꾸고, 펼친 목록은 지금, 다음, 나중 순서로 정렬했다. 3시간보다 먼 일정은 남은 시간 대신 시각만 보인다. 1.39에서 시간을 정한 할 일이 막대 아래 칸으로 들어왔다. 이 무렵 성능을 재 보고서야 깜빡이는 '지금' 선이 노트 전체를 매 프레임 다시 그리고 있었다는 걸 알았다. 노트를 열어 둔 채 쉬기만 해도 Mac CPU가 61%였다.

![하루 띠 2차](screenshots/process/daystrip-round2.png)

3차 (Mac 1.40, Windows 1.25). 카드 상자를 빼고 종이 위의 한 구역으로 만들었다. 막대는 얇게 하고, 지금 하는 일을 손글씨로 크게 쓰고, 남은 시간은 왼쪽 동그라미에, 그 아래 다음 두 줄을 둔다. 알림 고리와 문장은 뺐다. `하루 전체 ›`를 누르면 그 자리에서 하루 일정표가 펼쳐진다. '지금' 눈금은 깜빡이지 않고, 분이 바뀔 때만 다시 그린다.

![하루 띠 3차](screenshots/process/daystrip-round3.png)

![하루 일정표](screenshots/mac/day-open.png)

1차와 2차는 하루를 다 보여 주려고 했다. 써 보니 목록 위에서 필요한 건 지금 무엇을 하고 있고 얼마나 남았는지였다. 하루 전체는 한 번 누르면 나오는 곳으로 옮겼다.

카드 상자를 뺀 데는 다른 이유도 있다. 카드는 AI가 만든 디자인마다 나오는 모양이라, 그 티를 빼고 싶었다. 대신 사람들이 익숙한 방식대로 시간이 왼쪽에서 오른쪽으로 흐르는 막대 하나를 남겼다.

### 밤 종이

![밤 종이](screenshots/mac/night/note-today.png)

밤 종이는 검은 화면 대신 불을 끈 방에 놓인 종이 색으로 정했다. 종이 #2a2924, 먹 #ece6d6. 탭과 테이프는 어둡게, 세이지와 점토는 밝게 바꿨다. 일정 색은 밝기 85%로 낮추고 종이 결은 끈다. 창 바탕도 같은 색이라 창을 열 때 흰 화면이 번쩍이지 않는다. 모든 글자 쌍은 WCAG AA를 넘어야 한다.

## 메모 서랍

![메모 서랍](screenshots/mac/drawer-list-day.png)

메모는 할 일과 달리 어떤 앱을 쓰다가도 바로 적고 꺼내 보고 싶었다. 노트를 열고 메모 탭으로 가는 대신, 화면 끝에서 미끄러져 나오는 서랍으로 옮겼다(Mac 1.43, Windows 1.28). `⇧⌘D`(Windows `Ctrl+Shift+D`)나 화면 끝의 고양이 발 손잡이로 열고, 옆의 책갈피 하나가 폴더 하나다. 서랍 위쪽에는 종이로 오린 고양이 귀가 있다.

써 보며 세 번 고쳤다.

| 판 | 써 보니 | 고친 것 |
| --- | --- | --- |
| 1.43.0, 1.28.0 | 메모 탭이 서랍이 됨 | 줄 노트 한 장씩의 메모, 폴더 책갈피, 고정, `- [ ]` 체크 줄, 종이 네 가지(낮, 밤, 크라프트, 모눈) |
| 1.43.1, 1.28.1 | 밤 종이에서 글자가 눈에 안 들어오고, 서랍 설정을 찾기 어려웠다 | 쪽지와 서랍을 떼어 놓고(1.11:1 → 1.33:1) 회색 글자를 밝힘. 설정은 책상의 '메모 서랍' 칸으로 |
| 1.44.0, 1.29.0 | 메모가 늘자 어디쯤인지 찾기 어렵고, 메모끼리 구별이 약하고, 할 수 있는 일이 작은 버튼 안에 숨어 있었다. 메모 높이도 빡빡했다 | 날짜 묶음과 카드, 종류 표시, 우클릭 메뉴, 메모마다 종이, 바탕 네 가지 |
| 1.45.0, 1.30.0 | 카드 글자가 작고 회색이라 흐렸다. 카드에는 한 줄만 보였고, 줄 노트 선과 빨간 여백 선, 고치는 동안의 초록 테두리가 글보다 눈에 띄었다 | 글자 시안 B와 메모지 시안 D: 손글씨 제목 20 → 22pt, 미리보기는 본문 잉크로 세 줄까지, 줄 노트 선 없이 테이프 · 테두리 · 그림자만 |

1.44는 시안부터 다시 받았다. 데스크톱 메모 앱 다섯 개와 HIG의 메뉴 규칙을 살펴본 뒤 메모끼리 나누는 방법만 바꾼 시안을 여섯 장 받았다. 간격만 넓히기, 테이프 조각, 살짝 기울이기, 인덱스 카드 같은 안이었다. 거기서 한 번 더 '사람들에게 익숙한 모양'으로 좁혀 날짜 묶음과 카드를 골랐다.

- **날짜로 묶기**: Apple 메모처럼 고정, 오늘, 어제, 이번 주, 지난주, 달, 해 머리말 아래 모은다. 머리말이 날을 말해 주니 카드에는 시간만 짧게 쓴다.
- **카드는 같은 자리에**: 손글씨 제목과 오른쪽 시간, 한 줄 미리보기, 종류가 있으면 그 아래 작은 표시. 메모 사이는 16pt, 제목만 있어도 카드 높이는 68pt. 카드마다 폴더 색 테이프 한 조각이 붙는데, 자리와 기울기는 메모 id로 정해서 다시 열어도 같다.
- **종류 표시**: 글은 바꾸지 않고 링크(`youtube.com/watch`, 누르면 브라우저), 전화번호(`010-1234-5678`, 누르면 복사), 체크 목록(`2/4`)을 작게 알려 준다. 제목이 주소뿐이면 `youtube.com 링크`로 보인다.
- **우클릭 메뉴**: 메모, 책갈피, 서랍 빈 곳에 메뉴를 달았다. 메뉴에서 하는 일은 모두 단추, 키, 끌기로도 된다. Mac은 macOS 메뉴라 키보드와 VoiceOver로도 쓰고, Windows는 `Shift+F10`과 메뉴 키로 연다.
- **메모마다 종이, 바탕**: 메모 한 장만 다른 종이로 바꾼다. 서랍 바탕은 불투명(기본), 반투명, 강하게, 없음. Windows의 반투명은 Windows 11 아크릴이고 실제 PC에서는 아직 보지 못했다.

네 종이 모두 서랍 종이를 메모지보다 한 단 진하게 하고 메모지에 1pt 테두리를 둘렀다. 메모지 위 시간과 안내 글자는 6:1 이상이다(낮 6.16, 밤 6.06, 크라프트 8.58, 모눈 6.14).

서랍 종이는 낮 `#e6dbc3`, 밤 `#1c1a17`, 크라프트 `#cdb187`, 모눈 `#dde6f0`이고, 낮 메모지는 `#fffdf7`에 테두리 `#d0c2a3`, 밤 메모지는 `#3d3a34`에 테두리 `#5a554b`다.

![메모 서랍 새 모습](readme/cards/drawer-ko-light.png)

1.45(Windows 1.30)에서는 서랍 글자를 다시 봤다. 글자만 바꾼 시안과 메모지 모양만 바꾼 시안을 따로 받아 둘을 골랐다.
- **글자(시안 B)**: 글꼴 설정과 상관없이 카드 손글씨 제목은 22pt에 획을 아주 조금 두껍게 했다. 미리보기는 11.5pt 회색에서 13pt 본문 잉크를 한 단계만 옅게 한 색으로 바꿨다. 네 종이 모두 예전 회색보다 진하다(낮 6.97 → 7.01, 밤 7.60 → 7.90:1). 펼친 메모는 14pt, 줄 간격 26pt.
- **카드에 더 많이**: 미리보기가 본문 세 줄까지, 체크 목록은 앞의 항목 세 개를 작은 체크 상자와 함께 보여 준다. 짧은 메모는 있는 줄만큼이라 빈 줄이 없다.
- **메모지(시안 D)**: 줄 노트 선과 빨간 여백 선을 뺐다. 종이 느낌은 폴더 색 테이프, 1pt 옅은 테두리와 그림자, 위쪽 끝의 작은 뜯어낸 자국으로 남겼다. 펼친 메모와 고치는 칸에는 테두리 상자 대신 그림자가 조금 깊어지고, 커서로만 고치는 중임을 알린다. 키보드로 고른 카드는 폴더 색 옅은 테두리를 더해 색만 보지 않아도 알 수 있다.
- **고정은 핀**: 발바닥은 메모 서랍 자신(손잡이, 아래 줄)에만 쓰고, 고정은 핀으로 바꿨다. 아이콘 하나에 뜻 하나다([아이콘표](icons.md)).

## 단색 탭

노트의 탭, 서랍의 책갈피, 화면 끝 손잡이는 1.34부터 와시 테이프처럼 옅은 줄무늬였다. 줄무늬 없는 단색 시안을 받아 B(꿀 · 라벤더, 1pt 테두리)를 골랐다.
- 탭 이름과 숫자는 고르든 말든 같은 진한 잉크다. 밤에는 탭 색 위에 어두운 잉크라 오늘 6.9:1, 앞으로 6.1:1이다.
- 책갈피는 폴더 색 그대로, 고정은 낮 · 밤에 오늘 탭 색을 따른다. 손잡이는 모든 종이에서 옅은 크림색 하나에 발바닥(6.9:1)이다.
- 같은 판에서 쪽지 테이프도 단색이 됐다. 한 화면에 옛 줄무늬와 새 단색이 섞이면 덜 다듬어진 앱처럼 보여서다(UI/UX 점검).

## 할 일 스페이스

![오늘 한 장의 색 띠와 회사만 보는 중](readme/cards/spaces-ko-light.png)

할 일을 회사, 집, 공부처럼 나누고 싶었다. 그래도 오늘 할 일을 한 장에서 다 보는 건 놓치고 싶지 않았다. 그래서 **나누되 쪼개지 않기**로 정했다(Mac 1.45, Windows 1.30).

먼저 다른 앱을 봤다. Things의 Area, Todoist의 프로젝트, Apple 미리 알림과 Microsoft To Do의 목록, macOS 집중 모드 필터, Arc 브라우저의 Spaces. 공통점은 넷이었다. 갈래는 할 일의 속성이고, ‘오늘’은 늘 모든 갈래를 모으고, 빠른 입력에 `#`를 쓰고, 거르기는 잠깐이다. Arc처럼 공간을 통째로 바꾸는 방식만 ‘한 장’과 맞지 않았다.

시안(①–⑤)을 놓고 이렇게 정했다.
- **섞어서, 줄 왼쪽 끝 색 띠만**: 스페이스가 있는 할 일에만 4pt 띠가 붙고, 마우스를 올리면 이름이 보인다. 스페이스별로 묶기는 다음 단계로 미뤘다.
- **한 스페이스만 보기는 잠깐**: `모든 스페이스 ▾`나 단축키로 고르면 ‘회사만 보는 중 · 다른 할 일 4개는 숨겼어요 · 모두 보기’가 늘 보이고, 다음 날 새벽 4시에 저절로 풀린다. 거르는 동안 적는 할 일은 그 스페이스로 들어간다.
- **입력 줄의 `#`**: Todoist처럼 `#회사`, 앞부분(`#회`)과 초성(`#ㅎㅅ`)도 된다. 없는 이름이면 칩이 `+ 새 스페이스 ‘세탁’`이 된다.
- **이름은 스페이스**: 메모 서랍의 ‘폴더’와 헷갈리지 않게 했다. 색은 폴더와 같은 8색이다.

고르지 않은 안: 메모 폴더를 할 일에도 같이 쓰기(할 일만 나누고 싶었다), 공간 통째로 바꾸기, 태그 여러 개(띠가 여러 개가 되고 거르기가 복잡해진다), 오늘 탭을 스페이스별 탭으로 쪼개기.

Mac에서는 스페이스를 바꿀 때마다 머리말 버튼의 글자 너비가 달라져, 진행률이 제목 옆과 아래를 오가며 머리말이 움직였다. 버튼을 날짜 줄 끝으로 옮겨 제목 · 진행률 · 날짜 줄이 제자리에 있게 했다. Windows는 처음부터 고양이를 피해 날짜 줄 끝에 뒀다.

## 점검과 말

기능이 쌓이자 두 앱과 세 언어가 조금씩 어긋났다. 두 번의 UI/UX 점검과 한 번의 문구 점검으로 고칠 것을 모으고, 사용자가 골라야 하는 것은 시안부터 만들었다([엔지니어링 6장](engineering.md#6-화면과-말-점검)).
- 할 일 우클릭 메뉴와 ⋯ 메뉴를 두 앱에서 같은 순서 · 같은 말 · 같은 아이콘으로, 줄에서 쓰는 키를 오른쪽에 보이게 했다.
- 할 일 줄에 마우스를 올리면 나오는 버튼을 다섯에서 셋(내일 · 알림 · ⋯)으로 줄였다. 제목이 덜 잘린다.
- 남은 시간은 시각과 헷갈리지 않게 길이로 쓴다. ‘1:01 뒤’ 대신 ‘1시간’ / ‘1분 뒤’, 타이머 ‘20:50’ 대신 ‘21분 남음’.
- 책상 목록 아이콘은 받침 없이, 고른 칸만 색 받침을 둔다.
- 말은 [글쓰기 가이드](writing.md)와 [용어표](terms.md)를 따른다. 버튼은 동사, 오류는 무엇을 못 했나 → 지금 상태 → 할 일, 고양이는 재촉하지 않는다([ADR 10](decisions.md#adr-10-화면의-말은-글쓰기-가이드-하나를-따른다)).

## 종이 디자인 시스템

종이 모양을 고른 건, 다들 화면에 익숙해도 플래너에 할 일을 적고 그렇게 공부하던 경험이 아직 강하다고 봐서다. 할 일이 종이에 적힌 것처럼 보이면 관리하는 느낌이 더 손에 잡힐 거라고 생각했다.

색은 모두 이름 붙은 토큰이고 두 앱이 같은 값을 쓴다(Mac `PaperTheme.swift`, Windows `src/renderer/base.css`).

| paper-2 | `#f5f1e7` | `#33322c` | 두 번째 면 |

세이지는 지금, 끝냄, 선택에만 쓰고 점토는 곧, 늦음, 지우기에만 쓴다. 쓰는 색이 적어서 붉은색이 보이면 시간이 급하다는 뜻으로 읽힌다.

글꼴은 할 일 제목에 손글씨(한글은 HanJang Pen과 Brush, 영어와 네덜란드어는 Caveat와 Kalam), 조작과 숫자에 시스템 글꼴을 쓴다. 숫자는 고정 폭이다. HanJang은 나눔 손글씨 글꼴에서 낱자(ㄱ, ㅇ, ㅏ …)의 폭을 잉크에 맞게 줄인 것이다. 원래 글꼴로는 한글을 입력하는 동안 ㅇ이 '오'로 바뀔 때마다 커서가 앞뒤로 튀었다(Mac 1.11).

체크하면 네모가 0.85에서 1로 커지고, 연필 선이 0.22초 동안 왼쪽에서 오른쪽으로 그어진다. 움직임 줄이기를 켜면 모두 멈춘다.

## 고양이

딱딱한 디자인은 쉽게 무시하게 되고 금방 지루해진다. 고양이는 그걸 덜려고 넣었다.

고양이 그림은 이미지 생성 도구로 만들었다. 앉은 고양이 그림 한 장을 기준으로 고르고, 다른 포즈는 모두 그 그림을 첨부해 같은 스타일 문단으로 요청했다. 나온 그림에서 쓸 것을 골랐고, `prepare-pet-art.swift`로 1024 × 1024 크기, 같은 바닥선(높이 약 93%)에 맞췄다. 바닥선이 다르면 포즈가 바뀔 때 고양이가 위아래로 튄다. 프롬프트와 검사 기록은 [`mac/art/`](../mac/art)에 있다.

처음에는 곰과 고양이 중 고를 수 있었는데, 1.7.2에서 곰을 빼고 고양이 하나로 정했다. 1.9에서는 정면을 보는 그림을 자르거나 가짜 다리를 붙이지 않고, 한쪽 앞발을 축으로 몸을 기울여 뒤뚱거리며 걷게 했다.
